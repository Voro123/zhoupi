# 卫戍终端 · Garrison Nexus

国服「卫戍协议·规程·序列Ⅰ」速查网站。纯静态 HTML/CSS/JavaScript，无登录、数据库或私有 API。收藏、阵容存于浏览器 localStorage，可导入导出 JSON。

## GitHub 与腾讯云部署

仓库已包含完整 `dist/`，可直接由腾讯云 EdgeOne Pages 拉取部署；请保留该目录中的页面、JSON 和全部图片。`npm run build` 仅使用提交文件与 Node 内置模块，不需要原始游戏表、Python 或安装开发依赖。

已提供 `edgeone.json`：根目录选项目根目录，框架选 Other，安装命令 `node --version`，构建命令 `npm run build`，输出目录 `dist`。详细的上传步骤、子目录设置与迁移说明见 [DEPLOYMENT.md](DEPLOYMENT.md)。

从现有工作目录生成不带 Git 历史、旧托管配置和本地缓存的上传副本：

```sh
npm run export:github -- ../garrison-terminal-github
```

## 运行

直接部署 `dist/` 到任意静态托管，或执行：

```sh
npm run dev
```

浏览器访问 `http://localhost:4173`。查询不依赖第三方 API；全部 222 名独立角色的头像和立绘已打包。在线字体不可用时自动使用系统字体。

## 快速选人与图片

默认采用高密度头像视图，只显示头像与实际盟约图标。单击头像选入／移出阵容；悬浮头像查看完整驻守特质和基础技力，移开立即关闭；右键或 Shift+Enter 打开完整档案。手机点按头像选入／移出阵容，长按约 450ms 从右侧抽屉查看干员介绍；滑动会取消长按，松手不会误选。点按盟约图标查看效果。工具栏仍可切回大卡片。

独立盟约图鉴页已移除，盟约效果与层数试算放进筛选栏和详情等位置的盟约悬浮面板。干员网格里的盟约小图标不弹出悬浮框。收藏和对比操作放在完整档案中。筛选栏、档案详情及阵容中的盟约均使用真实图标。

干员列表默认从Ⅰ阶到Ⅵ阶分组，各阶强制换行并显示独立分隔标题。名称和技力排序也保留分组，只在组内排序。干员列表首次显示 64 项，向下滚动接近末尾后用 IntersectionObserver 自动追加下一批，不重建已显示的网格，也不需要点击“加载更多”。查询或筛选后会从新的结果集开始。

另外已本地打包 26 个盟约图标、61 个角色策略发起人头像及 70 个装备图标，逐图来源保存在 `dist/assets/catalog.json`。装备按客户端 `sktok_acarm…` ID 匹配，避免改名装备配错图。重建需运行：

```sh
python3 scripts/download_catalog_assets.py
```

## 手机小屏幕

800px 及以下保持局内专注布局，隐藏赛季横幅、侧边导航和重复标题；搜索与筛选同排，首页直接切换初始／精锐。收藏与高级选项收在可折叠筛选区，筛选完成后保留选人列表。

介绍抽屉保留左侧列表可见，支持独立滚动、固定关闭按钮和遮罩点按关闭。关闭后恢复原来的滚动位置与已加载干员；底部阵容九个位置完整显示，盟约进度横向滑动查看。已适配安全区、横屏和 320px 小屏幕，搜索与主要输入框避免 iOS 聚焦自动放大。

`node scripts/mobile-ui-test.mjs` 使用触屏手势验证点按、长按、滑动取消、列表位置恢复、筛选收放、养成状态和小屏幕溢出；已纳入 `npm test`。

## 用途标签：高效叠层与经济干员

`dist/operator-roles.js` 只高亮当前初始／精锐状态下，满足触发条件后每回合可重复产层达到 **4 层及以上** 的干员。不标战力。

- 计入休整阶段和战后结算；按用户要求，多个受益盟约的新增层数可以相加达到 4；有邻位收益时注明内部条件，不假定未知邻位已经配置。
- 固定产层读取对应阶段的黑板数值；寒檀等同一盟约的不同重复阶段会合计。战斗类读取每次产层及明确的单场上限，注明达到 4 所需触发次数，上限不当作实战保底。
- 数量条件类计算达到 4 所需的存活人数、同一行人数、刷新次数、花费等，条件保留在内部分类数据中。按受益盟约数量汇总对应产层值。
- 获得时一次性叠层（包括逻各斯）、每回合定额／上限不足 4、仅提高上限或增幅、临时层转固定层、收益未定的复制都不高亮。烈夏的每场临时层单独注明，临时层不等于永久积累。
- 当前固定池的初始状态高亮 55 名，精锐状态高亮 61 名；经济身份保持 26 名。低效和一次性叠层仍可在驻守特质原文查看。75 名自选候选不强行归类。

青色边框与“叠”角标仅代表符合上述门槛；虚线和星号表示需要满足触发／数量条件。金色经济角标和已入队的绿色勾选保持独立。筛选仍与盟约、职业、等阶组合，前端只保留颜色、角标与筛选，不展示判定细则，并保留各阶换行、自动加载、头像移开立即关闭和小盟约图标不弹窗。

## 本地阵容预设

在阵容规划中为当前阵容命名，点击“保存为新预设”。预设保存完整干员列表、初始／精锐状态和 8／9 人上限，并以独立快照保存在 `garrison-nexus-presets-v1` 的 localStorage 中。加载预设会替换当前草案，不修改该预设。

预设支持搜索、加载、覆盖、重命名、删除；覆盖和删除后的提示可点击撤销。界面分批展示列表，保存数量没有人为上限，不会因为只显示前 12 项就丢弃其余数据。存储总量受浏览器配额限制；保存失败会显示“未保存”，保留原数据。浏览器清理站点数据会移除这些本地预设。

- 最新期次核对至 2026-11-17：2026-11-08 开放的「规程·序列Ⅰ」。官方公告：https://ak.hypergryph.com/news/0787.html

- 固定池 143 槽位（含 2 个特殊获取槽位）、67 组补位关系；固定池外 75 名六星自选候选（包括六星原型），按Ⅴ／Ⅵ阶各提供一套查询记录，不能当成 150 名不同干员。
- 26 盟约、61 角色策略及全部 70 个可见装备条目。最终条目数以 `dist/data.json` 为准。
- 初始／精锐均由各槽位配置决定；技能等级为 4／7，逐一解析技能黑板参数，无未解析的技能占位符。包含技力、回复类型、持续时间、充能、天赋、裸属性及固定槽位默认模组。
- 自选候选的核心盟约由 `mainPower/subPower` 与客户端 `powerIdList` 匹配，不编造专属驻守特质。默认查看最高序号技能，详情能查各技能；自选模组由游戏内决定，工具未擅自指定。实际可选性受持有、局内禁用与自选配置限制。
- 显示的是基础技能参数。技能、天赋、模组、持有、盟约、装备等会影响实战数值。裸属性通过等级插值，另列模组及天赋，避免重复计入。部分专用自动施放方案只保留已知配置标记。
- 盟约层数试算读取 `effectDescParamDataDict` 和效果黑板，包括配置中明确给出的上限；结果不代表人数、站位等条件自动满足。

`dist/data.json` 是独立数据接口，UI 不内嵌干员数值，可扩展多期选择、站位与装备模拟。当前不进行战斗伤害模拟，也不自动拉取后续游戏更新。

## 重新提取与校验

初次下载精确快照：

```sh
python3 scripts/fetch_sources.py
python3 scripts/build_data.py
npm run data:check
npm run build
```

数据提取脚本断言固定池数、自选池数、技能索引与全部技能占位符。`npm run data:check`（即 `--check` 模式）逐项比对已提交 JSON，不会静默覆盖数据；它需要先下载原始表。部署命令 `npm run build` 独立校验已提交的静态资源与逻辑，不需要这些原始表。原始表因体积和可复现性不提交，生成的完整 JSON 已提交并可直接使用。

重建贴图需安装 `requirements-assets.txt`，然后运行 `python3 scripts/download_assets.py`。游戏贴图、角色、名称、游戏文本等版权属于上海鹰角网络科技有限公司及其关联公司；资源整理来源为 [ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)。站点为非官方玩家工具。

### 本局 BAN 与购买价格

- 干员头像右下角显示一次购买所需资金。按本期 `shopCharChessInfoData.purchasePrice` 读取；真理与至简的购买价特质覆盖为 1。温蒂的售出价格不影响购买价。隐藏特殊获取槽位显示「—」，自选Ⅴ／Ⅵ阶均为 4；不预测策略、盟约或局内临时折扣。
- 「本局 BAN」在列表上方展开，可记录本期 10 个核心盟约与 16 个附加盟约的置灰结果；立即过滤固定池和自选候选，和已有搜索、用途、等阶筛选叠加。刷新页面保留，新一局可清空；清除普通查询条件不会清掉本局 BAN，也不会删除阵容或预设。
- 规则依据本期游戏入门教程（[PRTS 转录](https://prts.wiki/w/卫戍协议·规程/战场一览)）：核心盟约置灰则所属干员不入池；附加盟约须本人所有附加盟约都置灰才不入池。多核心干员任一核心禁用即排除；无附加盟约不视为全部禁用。绝技为精锐通用效果，不纳入个人卡池排除判定。初始／精锐使用相同原始归属，自选候选不因 BAN 改为协防。
- 页面不模拟开局抽选数量或代替游戏抽选；玩家按本局简报勾选，无固定 BAN 数量限制。判定逻辑位于 `dist/catalog-rules.js`。
- `scripts/catalog-rules-test.mjs` 验证价格例外、多个核心、部分／全部附加盟约、无附加、自选及特殊获取；`scripts/ban-ui-test.mjs` 验证筛选组合、本地持久化、头像／卡片角标、阵容保留和移动布局。
